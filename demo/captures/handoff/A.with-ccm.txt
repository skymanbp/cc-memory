Decisions I made along the way:

- **Schema and read path.** One table: `entries(id INTEGER PRIMARY KEY AUTOINCREMENT, amount REAL NOT NULL, note TEXT NOT NULL DEFAULT '')`, read back `ORDER BY id` so `entries()` preserves insertion order. `entries()` still returns `[{"amount": ..., "note": ...}]` dicts, and `total()`/`export_json()` are now built on top of it, so the JSON export is byte-shape-identical to before (verified: `[{"amount": 1.0, "note": "one"}]`).
- **Kept the constructor default as `"tally.json"`.** You asked for the public interface exactly as-is, and `cli.py` (untouchable) also defaults `--file` to `tally.json`. So the SQLite database can live at a `.json`-named path — cosmetically odd, but changing the default would have broken the interface contract without changing what the CLI actually does.
- **Legacy-file migration instead of crashing.** Because the default path is unchanged, anyone with an existing JSON-era `tally.json` would otherwise hit `sqlite3.DatabaseError: file is not a database` on first run. On open, `Store` sniffs the first 16 bytes: if the file exists and lacks the `SQLite format 3\0` magic header, it parses it as the old JSON array, replaces the file with a fresh database, and inserts the old entries. A file that is neither format raises a clear `ValueError` rather than a cryptic sqlite error. Verified: legacy entries survive migration and appear in the export.
- **Connection-per-operation** (`contextlib.closing` + the connection's own transaction context manager) rather than a long-lived connection held by the instance. `Store` has no `close()` in its public interface and I couldn't add one, so per-op connections avoid leaking Windows file handles across the multiple `Store` instances the tests (and CLI) create; commit-on-success/rollback-on-exception comes free from `with conn:`.
- **The `ValueError` fix checks `float(amount) < 0` after conversion**, so `-0.0` and `0` are still accepted (zero is not negative) and the error message reports the normalized value. I verified it raises manually but did **not** add a regression test, since you scoped changes to `tally/store.py` only — worth adding `assertRaises(ValueError)` to `tests/test_store.py` later if you want it locked in.
